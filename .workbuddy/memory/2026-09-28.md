## 经验：AppKey 弹窗排查顺序

「未配置appkey或配置错误」弹窗的四个排查点，按顺序核对：
1. 开发者中心登记的包名 == `build.gradle` 的 `applicationId`
2. 开发者中心登记的 SHA1 == APK 实际签名证书 SHA1（`unzip -p x.apk META-INF/CERT.RSA | keytool -printcert`）
3. appid == `dcloud_control.xml` 的 `app appid` == `assets/apps/__UNI__XXX/` 目录名 == www/manifest.json 的 `id`（三者必须一致）
4. AppKey 写入 `AndroidManifest.xml` 的 `dcloud_appkey`

注意：DCloud 上改了包名/SHA1 后，**AppKey 会变**，必须重新生成并回填。

## 复用要点

只换 AppKey 时不需要重新编译前端，直接改 manifest + 跑 gradle 即可（约 1.5 分钟）。
换 appid 才需要重新编译前端（`uni-cli-build` 里跑 uni-build）并重建 `assets/apps/__UNI__XXX/www`。

## 【重要】卡启动页（splash 不消失）的根因与修复

现象：AppKey 弹窗解决后，App 卡在启动页一直转圈。
根因：**编译产物缺 `app-view.js`**。

- uni-app app-plus 是双线程：service 层（`app-service.js`）+ view 层（`app-view.js`）。
  `__uniappview.html` 里 `<script src="app-view.js">`，缺了它视图层 webview 永远起不来，
  splash 就关不掉 —— 表现为"一直转圈"。
- 判断方法：`ls dist/` 看有没有 `app-view.js`。正常的 v3 编译器产物约 180KB
  （残缺时只有 78KB 或是干脆不存在）。
- 为什么会缺：view 层编译时 sass 报错，webpack 因 `noEmitOnErrors=false` 仍"编译成功"，
  于是静默丢掉了 app-view.js，命令行还显示 Build complete。

### 三个坑（都在 uni-cli-build 里，已修）

1. **dart-sass 1.32 + Windows URI 报错**：`Uri d:%5C... must have scheme 'file:'`。
   sass-loader 8 给 dart-sass 返回 Windows 绝对路径，而 dart-sass 要 `file:` URI。
   修：patch `node_modules/@dcloudio/vue-cli-plugin-uni/packages/sass-loader/dist/webpackImporter.js`
   —— 用 `pathToFileURL` 包一层返回 `file`，并在 `dirContextFrom` 里用 `fileURLToPath`
   把回传的 URI 还原成本地路径（否则二级 import 的目录会算错）。
2. **vue-cli 的 `loaderOptions.scss || loaderOptions.sass` 是二选一**（见
   `@vue/cli-service/lib/config/css.js`）。一旦在 vue.config.js 里配了 `scss`，
   uni-app 注入在 `loaderOptions.sass.prependData` 的 uni.scss 就被**整体覆盖**，
   导致 uview 组件的 `$u-*` 变量报 `Undefined variable`。必须在自己的 scss 配置里补回。
3. uni.scss 里 `@import 'uview-ui/theme.scss'` 这种**包路径**在 sass importer 里解析不了
   （哪怕配了 includePaths）。改为在 vue.config.js 的 `prependData` 里直接注入
   theme.scss 的**绝对路径**（src/uni.scss 只有这一行，等价）。
4. postcss-loader 无显式 options 时会去根目录找配置文件，找不到就报
   `No PostCSS Config found`。补一个 `postcss.config.js`（内容 `module.exports = { plugins: {} }`）。

## 内置 zyfun 视频源（tbl_site）

用户给了 zyfun 导出的配置 `zyfun_config_20260928_005032.json`（89 条源）。

**关键：ZY Player 原版只支持 maccms 的 XML 接口**（request.js 用 fast-xml-parser 解析 `<rss>`），
而 zyfun 这批源是 **JSON 接口**（`api.php/provide/vod/`，返回 `{"code":1,"list":[],"total":N}`）。
直接内置会一点就报错，所以给 request.js 加了 json 分支（`isJson` + `mapVideo/mapPage/mapPlayList`），
XML 路径完全保持原样。

- 工具：`uni-cli-build/probe_sites.js`（探测+转换，含失败重试）、`test_json_api.js`（验证解析逻辑）。
- 探测结果：89 条去重 74 条，可用 16 条（json），按 total 降序；23 条域名已失效(ENOTFOUND)，
  其余超时/证书/HTML。已按 name 去重 → 内置 72 条，启用 15 条（失效的 isActive=false，
  用户可在「源管理」手动开启）。
- 生成结果：`utils/initSite.json`，每条带 `type: 'json'|'xml'`（site.vue 会显示这个字段）。
- **maccms json 接口的坑**：分类只在 `?ac=list` 返回里带（ac=videolist 没有 class 字段）；
  资源量字段叫 `total`（XML 里叫 recordcount）。
- 顺带放宽 `pages/detail/detail.vue` 的播放地址过滤：原来只认 `.m3u8`，
  现在优先 m3u8、没有则退取任意 http 地址。
- 注意：db.init 只在本地无数据时写入内置源，**换源后必须卸载重装**（或清应用数据）才会生效。

## 播放改走第三方播放器（弃用内置 video 组件）

用户点播放时报「打包时未添加 videoplayer 模块」——离线打包没引入原生播放器。
定位：SDK 的 `SDK/libs/weex_videoplayer-release.aar`（+ `media-release.aar` 带 ijkplayer so，
约 12MB）没放进 `android-package/simpleDemo/libs/`。官方示例 `HBuilder-HelloUniApp` 是有的。
修法有两条，用户选了**不做内置播放器**：

- 方案 A（未采用）：把 `weex_videoplayer-release.aar` + `media-release.aar` 拷进
  `simpleDemo/libs/`（gradle 里已有 `fileTree(dir:'libs')`，拷进去即可）。代价：APK 涨约 30MB。
- 方案 B（**已采用**）：删除 `pages/play/play.vue` 的 `<video>` 组件，用 Android Intent
  `ACTION_VIEW` + `video/*` 调起系统里已装的播放器（MX Player / VLC / 系统播放器）。

实现要点（play.vue）：
- `launchPlayer()`：`plus.android.runtimeMainActivity()` +
  `plus.android.importClass('android.content.Intent'/'android.net.Uri')`，
  `setDataAndType(Uri.parse(url), 'video/*')`，`Intent.createChooser(intent, '选择播放器')`。
- 失败降级 `plus.runtime.openURL(url)`，再失败 toast 提示装 MX Player/VLC。
- 续播：`intent.putExtra('position', 秒*1000)`（MX Player/VLC 支持），标题用 `putExtra('title')`。
  历史进度仍由 `history.vue` 传 `initialtime`。
- 播放区改为可点击的封面（黑底 + 播放图标 + 「点击使用第三方播放器播放」），
  onLoad 自动调起一次；`playConfirm` 换集后重新调起。
- 移除了 `videoTimeUpdateEvent` / `updateHistory`（外部播放器拿不回进度，
  **续播进度不会再更新**，这是该方案的固有限制）。
- manifest.json（源码 + uni-cli-build/src 两处）的 `app-plus.modules` 从
  `{"VideoPlayer":{}}` 改成 `{}`，彻底不依赖原生模块。

产物：APK 仍是 30.79MB（没涨），app-service.js 含 `launchPlayer`，www/manifest.json 无 VideoPlayer。

## 首页顶部栏吸顶固定（同日追加）
- 需求：顶部栏（网站切换+资源统计+搜索框+分类栏）滚到下面会消失，改为常驻固定。
- 实现（`pages/film/film.vue`）：**不用 `position:sticky`**（App webview 下不稳），
  改用 `position:fixed` + 动态测高占位块：
  - `data.topbarHeight` 初始 0，`.topbar` 加 `:class="{'topbar-fixed': topbarHeight>0}"`
    （测到高度后才切 fixed，避免首帧未测高就固定导致抖动）。
  - `onReady` → `measureTopbar()`：`uni.createSelectorQuery().in(this).select('.topbar')`
    取 `res.height`；取不到时兜底 `(statusBarHeight||20)+120`。
  - 紧随其后放 `<view class="topbar-placeholder" :style="{height: topbarHeight+'px'}">` 顶开空间。
  - `.topbar-fixed{position:fixed;top:0;left:0;right:0;z-index:999;box-shadow}`。
- 校验：app-view.js 含 `topbar-fixed`、app-service.js 含 `topbarHeight`/`measureTopbar`。
- 产物 `ZY-Player-0.1.2-release.apk` 30.79MB（30793624 字节），versionCode 102。

## 版本号升到 0.2.0
升版本要改 **4 处**（漏一处就会出现"包是新版、App 里显示旧版"）：
1. `manifest.json`（根，HBuilderX 用的那份）
2. `uni-cli-build/src/manifest.json`（CLI 编译真正读的那份）
3. `android-package/simpleDemo/build.gradle` 的 `versionCode / versionName`
4. `pages/me/me.vue` 第 41 行「版本更新」cell 的 `value="x.y.z"`（**同步一份到 uni-cli-build/src/pages/me/me.vue**）
versionCode 规则取「去掉小数点」：0.1.2→102、0.2.0→200。
校验：产物 `dist/manifest.json` 里版本字段在 **顶层 `version.name/code`**（不是 `plus.version`，
也不是源 manifest 的 `versionName/versionCode`），已确认是 `{"name":"0.2.0","code":200}`。
产物 `ZY-Player-0.2.0-release.apk`（30793306 字节），aapt 读出 versionCode=200 versionName=0.2.0。
