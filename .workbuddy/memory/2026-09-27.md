## 追加：真机启动报「未配置appkey或配置错误」

用户装上后启动即弹此窗。原因确认：
- DCloud 自 3.1.10 起，**离线打包必须申请自己的 AppKey**，且 appid + 包名 + 证书SHA1 三者必须与离线工程完全一致。
- 离线 SDK `HBuilder-Integrate-AS` 里那个 `066a4d8ce7ab7e5e20574ce01d6d5522` 不是通用测试 key，是上一个项目（桶装水：appid `__UNI__961DCF4` / 包名 `com.shuitong.peisong` / test.jks）留下的，换身份就失效。
- SDK 内另两个示例（HBuilder-HelloUniApp、UniPlugin-Hello-AS）的 appkey 值是占位文字「开发者需登录https://dev.dcloud.net.cn/申请签名」，印证必须自申请。

申请条件（已核实）：注册 dev.dcloud.net.cn → **必须实名认证**（未实名不能创建应用）→ 我的应用 新建应用（类型 uni-app）→ 拿到新 appid（`__UNI__XXXXXXX`）→ 各平台信息 新增 Android → 填包名 + SHA1(+SHA256) → 生成离线 AppKey。
二次开发也能申请，DCloud 不校验代码归属，只认账号下登记的应用。

本工程待填值（签名 test.jks / alias key0 / 密码 123456）：
- 包名 `com.zyplayer.app`
- SHA1 `B6:BA:28:25:A2:68:43:01:34:B6:70:0C:B9:F1:DA:FF:DF:B5:B6:20`
- SHA256 `60:3A:4C:5D:92:29:ED:6E:17:5E:2F:DD:62:4D:2F:D6:1C:13:F9:BA:8C:27:7B:ED:12:D0:3B:25:3D:DB:87:31`

拿到 AppKey + 新 appid 后需改 4 处：
1. `manifest.json` 的 appid（源码 src 那份 + 重新编译 dist）
2. `android-package/simpleDemo/src/main/assets/data/dcloud_control.xml` 的 appid
3. `assets/apps/<旧appid>/` 目录名 → 新 appid
4. `AndroidManifest.xml` 的 dcloud_appkey

## 追加3：换新 AppKey 后仍报 appkey 错误（排查中）

已用只读方式把 APK 侧四项全部核实无误，问题锁定在开发者中心登记值不匹配：
- APK 签名 SHA1 核验法：`unzip -p xxx.apk META-INF/CERT.RSA > cert.rsa` 然后 `keytool -printcert -file cert.rsa`（能拿到 APK 实际所用证书的 SHA1，比看 build.gradle 可靠）
- 包名：`aapt dump badging` 看 `package: name=`
- appid：解压看 `assets/data/dcloud_control.xml` 和 `assets/apps/<appid>/www/manifest.json` 的 `id`，并 grep 是否有旧 appid 残留
- AppKey：`aapt dump xmltree xxx.apk AndroidManifest.xml | grep -A3 dcloud_appkey`

四项均正确 → 说明用户在 dev.dcloud.net.cn「各平台信息→Android」填的包名或 SHA1 与实际打包值不一致（最可能是填了别张证书的 SHA1，或包名不同）。待用户核对那两个值后，改 `applicationId`（对齐其登记包名）或换签名证书即可。
